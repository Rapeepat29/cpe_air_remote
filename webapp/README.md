# เว็บแอป RMUTT Save Energy

เว็บแอปที่ใช้ฐานข้อมูลและ API ชุดเดียวกับแอปบนมือถือ ต่างกันที่หน้าจอกว้าง
จึงออกแบบให้ "ดูข้อมูลได้ละเอียดและสะดวกกว่า" โดยเฉพาะหน้าข้อมูลไฟฟ้า
ที่วางตารางสิบกว่าคอลัมน์และเลือกอุปกรณ์ทีละหลายตัวได้ในหน้าจอเดียว

เปิดใช้งานจริงที่ <https://rmutt-energy.duckdns.org/>

> **ทำไมชื่อโฟลเดอร์ `webapp/` ไม่ใช่ `web/`**
> Flutter จองชื่อ `web/` ไว้สำหรับคำสั่ง `flutter build web` แล้ว
> (ในนั้นมี `index.html` ที่เป็นตัวโหลด Flutter Web และ `manifest.json`)
> ถ้าเอาเว็บแอปนี้ไปวางทับ Flutter Web จะ build ไม่ได้ จึงใช้ชื่อ `webapp/` แทน

## 1. ทำไมถึงเขียนแบบนี้

### ไม่มีขั้นตอน build

ทั้งโฟลเดอร์เป็น HTML + CSS + JavaScript ล้วน ใช้ ES Modules ของเบราว์เซอร์
โดยตรง ไม่มี webpack / Vite / npm install

เหตุผลคือเซิร์ฟเวอร์มี Caddy ที่เสิร์ฟไฟล์ static อยู่แล้ว การเพิ่มขั้นตอน
build หมายถึงต้องมี Node บนเครื่องที่ deploy, ต้องจำว่าแก้แล้วต้อง build ก่อน
และเวลาโปรเจกต์ถูกส่งต่อให้รุ่นน้อง ต้องมานั่งไล่ว่าทำไม `npm run build` พัง
สิ่งที่ได้กลับมาคือความสะดวกตอนเขียนโค้ด ซึ่งไม่คุ้มกับเว็บขนาด 9 หน้า

ผลข้างเคียงที่ต้องยอมรับ: ต้องเปิดผ่าน `http://` หรือ `https://` เท่านั้น
เปิดไฟล์ `index.html` ด้วยการดับเบิลคลิก (`file://`) จะไม่ทำงาน เพราะ
ES Modules ถูกกติกา CORS ห้ามไว้

### ไม่มีไลบรารีภายนอกเลย

กราฟวาดเป็น SVG เอง ไอคอนเขียนเป็น SVG เอง ไม่มีอะไรดึงจาก CDN
ยกเว้นฟอนต์จาก Google Fonts ซึ่งเป็นของเสริมล้วน ๆ — ถ้าเครือข่ายของ
มหาวิทยาลัยเข้าไม่ถึง ตัวหนังสือจะถอยไปใช้ฟอนต์ไทยที่มีในเครื่อง
(Sarabun / Leelawadee UI / Tahoma) และทุกอย่างยังใช้งานได้ปกติ

### ดึงข้อมูลซ้ำเป็นรอบ ไม่ใช้ WebSocket

`store.js` ถามเซิร์ฟเวอร์ทุก 10 วินาที (ข้อมูลสด) ถึง 2 นาที (สรุปค่าไฟ)
Backend ปัจจุบันไม่มีช่องผลักข้อมูลออกมา การเพิ่ม WebSocket ต้องแก้ทั้ง
Express, Caddy และ Docker ซึ่งเสี่ยงกว่าประโยชน์ที่ได้ในระบบขนาด 15 บอร์ด

แท็บที่ถูกซ่อนไว้จะหยุดถามเซิร์ฟเวอร์ และดึงใหม่ทันทีเมื่อกลับมาดู

### นาฬิกานับถอยหลังเดินในเบราว์เซอร์

เซิร์ฟเวอร์ส่ง `autoOffDeadlineAt` มาเป็นเวลาเส้นตาย เบราว์เซอร์นับเอง
ทุกวินาที ไม่ได้ถามเซิร์ฟเวอร์ทุกวินาที เพราะเส้นตายเป็นค่าคงที่ ถามซ้ำ
ก็ได้คำตอบเดิม — หลักการเดียวกับที่แอปมือถือใช้

### ใช้ `#/ชื่อหน้า` เป็นเส้นทาง

ถ้าใช้ path จริง (`/rooms`) ผู้ใช้กด F5 แล้ว Caddy จะหาไฟล์ชื่อ `rooms`
ไม่เจอและตอบ 404 การใช้ hash จึงไม่ต้องตั้ง rewrite เพิ่มใน Caddyfile

แต่ละหน้าใน `views/` ส่งออกอ็อบเจกต์หน้าตาแบบนี้

## 3. สิ่งที่เว็บทำได้

| หน้า | ทำอะไรได้ | สิทธิ์ |
| --- | --- | --- |
| ภาพรวม | สรุปค่าไฟรายวัน/7 วัน/30 วัน พร้อมกราฟมีป้ายค่า, Building Pulse แสดงห้องที่กินไฟและห้องที่แอร์ทำงานอยู่, แจ้งเตือนล่าสุด, 5 ห้องที่ใช้ไฟมากที่สุด | ทุกคน |
| ห้องและควบคุม | ดูสถานะห้อง (มีคน/ไม่มีคน, นับถอยหลังปิดอัตโนมัติ) และเปิดรีโมตเต็มรูปแบบ: เปิด-ปิด, อุณหภูมิ, โหมด, พัดลม, ทิศลม, Eco/Turbo/Sleep/Quiet/ไฟหน้าจอ/ทำความสะอาด พร้อมค่า V/A/W/kWh/PF/Hz จาก PZEM | ทุกคน (เปลี่ยนชื่อ/โหมดตั้งค่า = แอดมิน) |
| ข้อมูลไฟฟ้า | เลือกระดับ (รวมอาคาร/รายห้อง/รายเครื่อง), ช่วงวัน, ค่าที่ต้องการจาก 16 ค่า, ดูเป็นตาราง แล้วส่งออกเป็น Excel ไทยหรืออังกฤษ | ทุกคน |
| ตารางเรียน | ดูตามวันและชั้น คาบที่กำลังเรียนอยู่จะถูกเน้น, เห็นว่าตารางที่ใช้อยู่เป็นภาคเรียนไหน, นำเข้าจาก Excel (.xlsx) หรือ CSV แบบเดียวกับแอป (เลือกได้ว่าแทนที่เฉพาะห้องในไฟล์ หรือเปลี่ยนภาคเรียนล้างทุกห้อง), ดาวน์โหลดตารางเป็น CSV สำรอง, ล้างตารางทั้งหมดช่วงปิดภาค | ทุกคน (เพิ่ม/แก้/ลบ/นำเข้า/ล้าง = แอดมิน) |

### ขั้นตอนแต่ละภาคเรียน

1. ต้นปีการศึกษา → **ปฏิทินภาคเรียน** → เพิ่มวันเปิด–ปิดของเทอม 1 และเทอม 2
   (ช่วงนอกวันเหล่านี้ ระบบถือว่าทุกห้องว่าง: ห้องว่างเกิน 5 นาทีปิดแอร์ และแจ้งเตือนเมื่อมีคนใช้)
2. ได้ไฟล์ตารางเทอมใหม่ → **ดาวน์โหลด CSV** เก็บตารางเทอมเก่าไว้ →
   **นำเข้าจาก Excel / CSV** → เลือก **"เปลี่ยนภาคเรียน — ล้างตารางเดิมของทุกห้อง"**
   นำเข้าช่วงปิดภาคได้เลย ตารางใหม่จะเริ่มใช้เองในวันเปิดภาค
3. ประชุม สอบ กิจกรรม ที่ไม่อยู่ในตาราง → **เพิ่มการใช้ห้อง** เลือกวันเดียว / ทุกวัน / ทุกสัปดาห์

ไม่ต้องล้างตารางตอนปิดภาคถ้าตั้งปฏิทินไว้แล้ว

การล้างหรือเปลี่ยนตารางไม่ลบข้อมูลไฟฟ้า ประวัติการแจ้งเตือน ห้อง หรืออุปกรณ์
ข้อมูลไฟฟ้า (`energy_hourly`) ไม่ได้ผูกกับตารางเรียนเลย
| การแจ้งเตือน | กรองตามสถานะและห้อง กดรับทราบ | ทุกคน |
| อัตราค่าไฟ | ดูอัตราปัจจุบันและตัวอย่างการคำนวณ | ดู = ทุกคน, แก้ = แอดมิน |
| ห้องและอุปกรณ์ | เพิ่ม/แก้/ลบห้อง, จองช่องติดตั้งบอร์ดแอร์และเซ็นเซอร์ (ได้โทเคน), เปลี่ยนชื่อ, เปิด-ปิดการปิดอัตโนมัติรายเครื่อง, ถอดอุปกรณ์ | แอดมิน |
| ผู้ใช้งาน | เพิ่มบัญชี เปลี่ยนสิทธิ์ เปิด-ปิดบัญชี ลบบัญชี | แอดมิน |
| ตั้งค่า | ธีมสี (เทา/ขาว/ดำ/เขียว/ตามเครื่อง) และขนาดตัวอักษร (ปกติ/ใหญ่/ใหญ่มาก) ของเครื่องนี้, สวิตช์รวมของระบบปิดแอร์อัตโนมัติ, แก้ข้อมูลส่วนตัว, เปลี่ยนรหัสผ่าน, สถานะ API/MQTT | ทุกคน (สวิตช์รวม = แอดมิน) |

### หน้าจอแต่ละขนาด

- **คอมพิวเตอร์** — แถบเมนูด้านซ้ายค้างไว้ เนื้อหากว้างไม่เกิน 1680px เพื่อไม่ให้บรรทัดยาวเกินอ่าน
- **มือถือ / แท็บเล็ตแนวตั้ง (กว้าง ≤ 820px)** — มีแถบเมนูล่าง 5 ปุ่ม (ภาพรวม ห้อง ข้อมูลไฟ แจ้งเตือน เมนู)
  แถบบนไม่ค้างหน้าจอ ลิ้นชักรีโมตเต็มจอ กล่องโต้ตอบเลื่อนขึ้นจากด้านล่าง
- **จอสัมผัส** — ปุ่มและชิปสูงอย่างน้อย 40–44px และช่องกรอกใช้ตัวอักษร 16px ขึ้นไป (iOS จะไม่ซูมหน้าเอง)

ทุกขนาดตัวอักษรในเว็บอ่านจากตัวแปร `--fs-*` ใน `tokens.css` ห้ามเขียน px เอง
ไม่งั้นการตั้ง "ตัวอักษรใหญ่" ในหน้าตั้งค่าจะไม่มีผลกับจุดนั้น

### สิ่งที่เว็บทำไม่ได้

**ตั้งค่าบอร์ดผ่าน Bluetooth** — ขั้นตอนนี้ต้องยืนใกล้บอร์ดและใช้บลูทูธของ
โทรศัพท์ส่งค่า Wi-Fi และ MQTT เข้าไป เว็บเบราว์เซอร์เข้าถึงบลูทูธของเครื่อง
ในแบบที่บอร์ดต้องการไม่ได้

เว็บจึงทำได้ถึงแค่ **จองช่อง** คือสร้างแถวในฐานข้อมูลพร้อมโทเคนอายุ 15 นาที
แล้วให้คนถือโทรศัพท์ไปทำต่อให้จบ ซึ่งยังมีประโยชน์ เพราะงานกรอกข้อมูล
(ห้อง หมายเลขแอร์ ยี่ห้อ เวลาเปิด-ปิด) พิมพ์บนคอมพิวเตอร์เร็วกว่ามาก
เหลือให้คนหน้างานแค่เลือกอุปกรณ์แล้ววางโทเคน

## 4. การพัฒนาบนเครื่องตัวเอง

เว็บต้องเสิร์ฟผ่าน HTTP จะเปิดไฟล์ตรง ๆ ไม่ได้ วิธีที่สั้นที่สุด

```powershell
# ในโฟลเดอร์ cpe_air_remote\webapp
python -m http.server 5500
```

แล้วเปิด <http://127.0.0.1:5500/?api=http://127.0.0.1:3000/api>

พารามิเตอร์ `?api=` ใส่ครั้งเดียวพอ ค่าจะถูกจำไว้ใน localStorage ของ
เบราว์เซอร์จนกว่าจะเปลี่ยนใหม่ ทำแบบนี้เพื่อให้ไฟล์ในโปรเจกต์ไม่ต้องมี
ที่อยู่เซิร์ฟเวอร์ฝังไว้ และเผลอ deploy ทับของจริงไม่ได้

ถ้า Backend รันคนละ origin ต้องตั้ง `APP_ORIGIN` ใน `.env` ของ backend
ให้มี `http://127.0.0.1:5500` ด้วย ไม่งั้นจะติด CORS

บนเซิร์ฟเวอร์จริงไม่มีปัญหานี้ เพราะเว็บกับ API อยู่โดเมนเดียวกัน

## 5. การขึ้นเซิร์ฟเวอร์

```powershell
# แก้แต่หน้าเว็บ (เร็ว ไม่ต้อง build ไม่ต้องรีสตาร์ท)
.\deploy\deploy-web.ps1

# แก้ทั้ง Backend และเว็บ
.\deploy\update-server.ps1
```

**แคชของเบราว์เซอร์:** Caddy ให้ไฟล์ใน `/assets` แคชได้หนึ่งชั่วโมง ส่วน `index.html` ไม่แคช
เวลาแก้ CSS หรือ JS ให้เปลี่ยนเลข `?v=` ใน `index.html` (ลิงก์ CSS ทั้งสี่ไฟล์และ `main.js`)
ทุกครั้ง และอย่าเพิ่ม export ใหม่ให้ไฟล์เดิมแล้วเรียกจากไฟล์อื่นทันที — คนที่เปิดเว็บไว้ก่อน deploy
อาจได้ไฟล์ใหม่ปนไฟล์เก่าจากแคช ของใหม่ที่ไฟล์อื่นต้องเรียกใช้ให้ใส่ไฟล์ใหม่แทน
(เช่น `prefs.js`, `icons-ui.js`) เพราะไฟล์ที่ไม่เคยโหลดย่อมไม่มีในแคช

ทั้งสองสคริปต์อัปโหลดลง `www.new` ก่อน แล้ว **คัดลอกเข้าไปใน** `www` ตัวเดิม
ไม่ใช่เปลี่ยนชื่อโฟลเดอร์ เพราะ Docker ผูก `./www` เข้ากับ container ของ Caddy
ตาม inode ไม่ใช่ตามชื่อ ถ้าใช้ `mv` สลับ Caddy จะยังชี้ไปที่โฟลเดอร์เดิมที่ถูกลบแล้ว
และตอบ 404 ทุกหน้า วิธีนี้ยังล้างไฟล์เก่าที่ถูกลบออกจากโปรเจกต์แล้วด้วย

เส้นทางบนเซิร์ฟเวอร์

| ที่อยู่ | คือ |
| --- | --- |
| `/` | เว็บแอป (`/opt/rmutt/www/index.html`) |
| `/status.html` | หน้าสถานะแบบเดิม |
| `/api/*` | Backend Express ผ่าน reverse proxy |

## 6. ความปลอดภัย

- โทเคน JWT เก็บใน `localStorage` ไม่ใช่ cookie เพราะ Backend ตรวจสิทธิ์จาก
  หัว `Authorization` อย่างเดียว การใช้ cookie จะทำให้ต้องคิดเรื่อง CSRF เพิ่ม
  โดยไม่ได้ประโยชน์กลับมา
- ทุกคำขอผ่าน `api.js` ที่แนบโทเคนให้เอง และเมื่อเจอ 401 จะล้างโทเคนแล้ว
  พากลับไปหน้าเข้าสู่ระบบทันที ที่เดียวทั้งระบบ
- ข้อมูลจากฐานข้อมูล (ชื่อวิชา ชื่ออาจารย์ ชื่อแอร์) ถูกใส่ลง DOM ด้วย
  `textContent` เสมอ ไม่ใช้ `innerHTML` — `innerHTML` ใช้เฉพาะกับไอคอน SVG
  ที่เขียนไว้ในโค้ดเท่านั้น
- สิทธิ์ที่ซ่อนปุ่มบนหน้าเว็บเป็นแค่ความสะดวก การบังคับจริงอยู่ที่ Backend
  (`requireAdmin`) เสมอ
