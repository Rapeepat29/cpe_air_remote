## ส่วนที่ 1 · ภาพรวมบนเซิร์ฟเวอร์

```text
   แอปมือถือ / เบราว์เซอร์                 ESP32 (Wi-Fi ในอาคาร)
         HTTPS 443                          MQTTS 8883
             │                                  │
             ▼                                  ▼
  ┌─────────────── เซิร์ฟเวอร์ Ubuntu  /opt/rmutt ────────────────┐
  │  caddy  ──/api/*──▶ backend ──▶ db (MariaDB, 127.0.0.1:3306)  │
  │    │                   └──────▶ mqtt (Mosquitto 1883 ภายใน)   │
  │    ├─ /            → www/        (เว็บแอป)                    │
  │    └─ /firmware/*  → firmware/   (.bin สำหรับ OTA)            │
  └──────────────────────────────────────────────────────────────┘
```

โฟลเดอร์บนเซิร์ฟเวอร์

```text
/opt/rmutt/
├── docker-compose.yml     (จาก deploy/)
├── Caddyfile
├── .env                   ★ ความลับทั้งหมด (สร้างโดย init-env.sh) อ่านได้เฉพาะ root/กลุ่ม docker
├── backend/               ซอร์ส Backend + Dockerfile
├── www/                   เว็บแอป (จาก webapp/)
├── firmware/              ไฟล์ .bin
├── mosquitto/config/      mosquitto.conf
├── mosquitto/certs/       ใบรับรอง (ก๊อปจาก Caddy)
├── mosquitto/data/        dynamic-security.json (บัญชี MQTT ทุกตัว)
├── db/data/               ข้อมูล MariaDB
├── caddy/data/            ใบรับรอง Let's Encrypt + access.log
├── backups/               ไฟล์สำรองฐานข้อมูล .sql.gz
└── *.sh                   สคริปต์ดูแลระบบ
```

พอร์ตที่ต้องเปิดจากภายนอก: **443** (HTTPS), **8883** (MQTTS), **80** (ขอใบรับรอง), **22** (SSH เฉพาะผู้ดูแล)
**ไม่เปิด**: 3306 (MariaDB), 1883 (MQTT ไม่เข้ารหัส)

## ส่วนที่ 3 · SSH — ควบคุมเซิร์ฟเวอร์จากระยะไกล

```powershell
ssh <user>@<host>                  # เข้าเซิร์ฟเวอร์ (ถามรหัส)
ssh -p 2222 <user>@<host>          # พอร์ตไม่ใช่ 22
ssh <user>@<host> "docker compose -f /opt/rmutt/docker-compose.yml ps"   # รันคำสั่งเดียวแล้วออก
```

ครั้งแรกจะถาม `Are you sure you want to continue connecting (yes/no)?` → พิมพ์ `yes`
(เป็นการจำ "ลายนิ้วมือ" ของเซิร์ฟเวอร์ กันการปลอมตัว)

### SCP — คัดลอกไฟล์ผ่าน SSH

```powershell
scp ไฟล์.bin <user>@<host>:/opt/rmutt/firmware/        # อัปโหลด
scp <user>@<host>:/opt/rmutt/backups/x.sql.gz .         # ดาวน์โหลดมาโฟลเดอร์ปัจจุบัน
scp -r โฟลเดอร์ <user>@<host>:/opt/rmutt/               # ทั้งโฟลเดอร์
scp -P 2222 ...                                          # พอร์ต (P ใหญ่สำหรับ scp)
```

### SSH Key — เข้าโดยไม่ต้องพิมพ์รหัส (แนะนำ)

```powershell
ssh-keygen -t ed25519
# กด Enter ตามค่าเริ่มต้น (จะตั้ง passphrase ก็ได้)
type $HOME\.ssh\id_ed25519.pub | ssh <user>@<host> "mkdir -p ~/.ssh && cat >> ~/.ssh/authorized_keys"
```

- สร้างกุญแจคู่: `id_ed25519` (**ลับ** อยู่ในเครื่องเรา ห้ามให้ใคร) และ `id_ed25519.pub` (สาธารณะ)
- ส่งกุญแจสาธารณะไปต่อท้าย `~/.ssh/authorized_keys` บนเซิร์ฟเวอร์
- ครั้งต่อไป `ssh` ไม่ถามรหัส และสคริปต์ `update-server.ps1` ทำงานต่อเนื่องได้

## ส่วนที่ 4 · Caddy และ HTTPS อัตโนมัติ

**Caddy** = web server ที่ **ขอใบรับรอง Let's Encrypt และต่ออายุให้เอง**
ทำ 3 หน้าที่ (ดู `deploy/Caddyfile`)

```text
{$DOMAIN} {                       ← โดเมนจาก .env (Caddy ขอใบรับรองให้โดเมนนี้)
    encode gzip                   ← บีบอัดให้โหลดเร็ว
    header { ... }                ← หัวความปลอดภัย (CSP, HSTS, nosniff ...)

    handle /api/* {
        reverse_proxy backend:3000     ← ① ส่งต่อคำขอ API ไป Backend
    }
    handle /firmware/* {
        root * /srv
        file_server                    ← ② เสิร์ฟไฟล์ .bin
    }
    handle {
        root * /srv/www
        file_server                    ← ③ เสิร์ฟเว็บแอป
    }
}
```

**Reverse proxy** = ตัวกลางที่รับคำขอจากโลกภายนอกแทน Backend
Backend จึงไม่ต้องจัดการ HTTPS เอง และไม่ต้องเปิดพอร์ต 3000 ออกนอก

**Let's Encrypt ขอใบรับรองอย่างไร**: ต้องพิสูจน์ว่าเราคุมโดเมนจริง
โดย Let's Encrypt จะเรียก `http://<โดเมน>/.well-known/acme-challenge/...` → **ต้องเปิดพอร์ต 80**
และ **DNS ของโดเมนต้องชี้มาที่เซิร์ฟเวอร์นี้แล้ว**

Mosquitto ใช้ใบรับรองชุดเดียวกัน (พอร์ต 8883) ผ่าน `sync-mqtt-cert.sh`
ที่ก๊อปจาก `caddy/data/...` ไป `mosquitto/certs/` แล้วส่งสัญญาณ `HUP`
ให้ Mosquitto โหลดใบใหม่โดยบอร์ดที่ต่ออยู่ไม่หลุด

`setup-vps.sh` ทำ 7 ขั้น
1. `apt-get update/upgrade` + ติดตั้ง curl, ufw, fail2ban (บล็อก IP ที่เดารหัส SSH), cron, dnsutils
2. ติดตั้ง Docker (จาก repository ทางการของ Docker) + เพิ่มผู้ใช้เข้ากลุ่ม `docker`
3. สร้าง swap 2 GB (หน่วยความจำสำรองบนดิสก์ กัน build แล้ว RAM ไม่พอ)
4. ตั้งเขตเวลา `Asia/Bangkok` + เปิด NTP (เวลาผิด = TLS ใช้ไม่ได้)
5. firewall (เฉพาะเมื่อใส่ `--firewall`): เปิดแค่ 22, 80, 443, 8883
6. เตรียมโฟลเดอร์และสิทธิ์
7. ตั้ง cron (ส่วนที่ 2.4)

## ส่วนที่ 6 · อัปเดตระบบครั้งต่อ ๆ ไป (จาก Windows)

| แก้อะไร | คำสั่ง | ใช้เวลา |
|---|---|---|
| Backend (และ/หรือเว็บ) | `.\deploy\update-server.ps1` | 1–3 นาที |
| Backend อย่างเดียว | `.\deploy\update-server.ps1 -SkipWeb` | |
| เว็บอย่างเดียว | `.\deploy\deploy-web.ps1` | ไม่กี่วินาที |
| รันขั้นบนเซิร์ฟเวอร์ซ้ำ (ไม่อัปโหลด) | `.\deploy\update-server.ps1 -SkipUpload` | |
| เซิร์ฟเวอร์อื่นชั่วคราว | `.\deploy\update-server.ps1 -Server 1.2.3.4 -User root` | |
| เฟิร์มแวร์ | `scp x.bin <user>@<host>:/opt/rmutt/firmware/` แล้วกดในเว็บ | |
| แอปมือถือ | เพิ่ม `version:` ใน `pubspec.yaml` → `.\build-apk.ps1` → แจก APK | |

### `update-server.ps1` ทำอะไร
1. `scp` ซอร์ส Backend (`src`, `scripts`, `database`, `package*.json`) + `update-remote.sh` + ไฟล์ deploy
2. อัปโหลดเว็บไป `www.new` แล้ว **คัดลอกเข้า** `www` (ไม่ `mv` — Docker ผูกโฟลเดอร์ตาม inode)
3. `ssh` สั่ง `update-remote.sh` บนเซิร์ฟเวอร์ ซึ่งทำ
   1. `docker compose up -d --build backend`
   2. รอจน backend พร้อม (สูงสุด 80 วินาที)
   3. migration ทุกตัว + `doctor.js --fix` (ปลอดภัยที่จะรันซ้ำ) + `sync-mqtt-cert.sh`
   4. `docker compose restart backend`
   5. reload Caddy
   6. ตรวจ `/api/health` = ok และ `/api/alerts` ฯลฯ ต้องตอบ **401** (แปลว่ามีเส้นทางแล้ว รอแค่ token)
      ถ้า **404** = โค้ดใหม่ยังไม่ขึ้น

ถ้ามีปัญหา

```powershell
ssh <user>@<host> "cd /opt/rmutt && docker compose logs --tail 80 backend"
ssh <user>@<host> "cd /opt/rmutt && docker compose ps"
```

### วิธี A · HeidiSQL ผ่านอุโมงค์ SSH (`db-tunnel.ps1`)

```powershell
.\db-tunnel.ps1
```

1. ssh ไปอ่าน `DB_USER` / `DB_PASSWORD` จาก `/opt/rmutt/.env` แล้วก๊อปรหัสใส่คลิปบอร์ด
2. เปิดหน้าต่างใหม่รัน `ssh -N -L 3307:127.0.0.1:3306 <user>@<host>` (**ห้ามปิดหน้าต่างนี้**)
3. บอกค่าที่ต้องกรอกใน HeidiSQL: Host `127.0.0.1`, Port `3307`, User ตามที่แสดง, Password `Ctrl+V`
   และ **ไม่ติ๊ก** SSH tunnel ของ HeidiSQL

**อุโมงค์ SSH** (`-L 3307:127.0.0.1:3306`) = อะไรที่ต่อพอร์ต 3307 บนเครื่องเรา
จะถูกส่งผ่าน SSH (เข้ารหัส) ไปออกที่ `127.0.0.1:3306` ของเซิร์ฟเวอร์
→ ดูฐานข้อมูลได้โดยไม่ต้องเปิดพอร์ต 3306 ออกอินเทอร์เน็ต

## ส่วนที่ 8 · สำรองและกู้คืน

```bash
sudo bash /opt/rmutt/backup-db.sh           # สำรองทันที
ls -lh /opt/rmutt/backups                   # ดูไฟล์
tail /var/log/rmutt-backup.log              # ผลของรอบอัตโนมัติ
```

`backup-db.sh` ใช้ `mariadb-dump --single-transaction` → gzip → `backups/rmutt-YYYY-MM-DD_HHMM.sql.gz`
เก็บย้อนหลัง `BACKUP_KEEP_DAYS` (14) วัน, ตรวจว่าไฟล์สมบูรณ์, ส่งไป `BACKUP_REMOTE` ถ้าตั้งไว้

กู้คืน

```bash
cd /opt/rmutt
gunzip -c backups/rmutt-2026-10-01_0230.sql.gz | \
  docker compose exec -T db mariadb -uroot -p"$(grep ^DB_ROOT_PASSWORD .env | cut -d= -f2)" rmutt_save_energy
```

- `gunzip -c` = แตกไฟล์ออกหน้าจอ (ไม่เขียนไฟล์)
- `|` = ส่งต่อให้คำสั่งถัดไป
- `$(...)` = รันคำสั่งข้างในแล้วเอาผลมาแทนที่ (ดึงรหัส root จาก `.env`)
- `\` ท้ายบรรทัด = ต่อบรรทัด (Bash)

> ⚠️ **backup ที่ไม่เคยลองกู้ = ยังไม่มี backup** ลองกู้ลงเครื่องทดสอบอย่างน้อยเทอมละครั้ง
