# 01 · พื้นฐานคอมพิวเตอร์และเครือข่ายที่ต้องรู้ก่อน

> บทนี้ยังไม่แตะโค้ดของโปรเจกต์เลย แต่ทุกบทหลังจากนี้ใช้ความรู้ในบทนี้ทั้งหมด
> ถ้าข้ามบทนี้ไป จะงงกับคำว่า "port 3000", "127.0.0.1", "JSON", "HTTPS" ไปตลอด

---

## 1. โปรแกรม, โปรเซส, และไฟล์

- **ไฟล์ (File)** = ข้อมูลที่เก็บในดิสก์ เช่น `server.js` เป็นไฟล์ข้อความธรรมดา
- **โปรแกรม (Program)** = ไฟล์ที่มีคำสั่งให้คอมพิวเตอร์ทำงาน
- **โปรเซส (Process)** = โปรแกรมที่ **กำลังรันอยู่** ในหน่วยความจำ

เปรียบเทียบ: สูตรอาหารในหนังสือ = โปรแกรม, พ่อครัวที่กำลังทำอาหารตามสูตร = โปรเซส

ในโปรเจกต์นี้ เวลาพิมพ์ `npm start` คอมพิวเตอร์จะเอาไฟล์ `backend/src/server.js`
มารันเป็นโปรเซสหนึ่งตัว โปรเซสนี้จะรันค้างไว้เรื่อย ๆ จนกว่าจะกด `Ctrl + C`

> 💡 **ภาษาโปรแกรม** คือภาษาที่ใช้เขียนสูตร โปรเจกต์นี้ใช้ 5 ภาษา
>
> | ภาษา | ใช้ที่ไหน |
> |---|---|
> | JavaScript | Backend (`backend/`) และเว็บแอป (`webapp/`) |
> | Dart | แอปมือถือ Flutter (`lib/`) |
> | C++ (แบบ Arduino) | เฟิร์มแวร์ ESP32 (`firmware/`) |
> | SQL | ฐานข้อมูล (`backend/database/schema.sql`) |
> | PowerShell / Bash | สคริปต์ช่วยรัน (`*.ps1`, `*.sh`) |

## 2. Client และ Server — คนสั่ง กับ คนให้บริการ

**Server (เซิร์ฟเวอร์)** = โปรแกรมที่ **รอ** ให้คนมาขออะไรบางอย่าง แล้วตอบกลับ
**Client (ไคลเอนต์)** = โปรแกรมที่ **ไปขอ**

เปรียบเทียบกับร้านอาหาร

| ร้านอาหาร | คอมพิวเตอร์ |
|---|---|
| ลูกค้า | Client (แอปมือถือ, เว็บเบราว์เซอร์) |
| พนักงานรับออร์เดอร์ | Server (Backend) |
| ห้องเก็บวัตถุดิบ | Database (MariaDB) |
| เมนู | API (รายการสิ่งที่ขอได้) |
| ใบสั่งอาหาร | Request (คำขอ) |
| จานอาหารที่ได้ | Response (คำตอบ) |

ในโปรเจกต์นี้

- แอป Flutter เป็น **client** ของ Backend
- Backend เป็น **server** ของแอป แต่เป็น **client** ของ MariaDB และของ Mosquitto
- ESP32 เป็น **client** ของ Mosquitto

แปลว่าโปรแกรมหนึ่งตัวเป็นได้ทั้ง client และ server ขึ้นกับว่ามองจากมุมไหน

## 3. IP Address — ที่อยู่บ้านของเครื่อง

ทุกเครื่องในเครือข่ายมี **IP address** เหมือนบ้านเลขที่ รูปแบบที่ใช้ในโปรเจกต์นี้คือ
IPv4 = ตัวเลข 4 ชุด คั่นด้วยจุด แต่ละชุดมีค่า 0–255 เช่น `192.168.1.50`

### IP พิเศษที่ต้องรู้จัก

| IP | ชื่อเรียก | ความหมาย |
|---|---|---|
| `127.0.0.1` | localhost / loopback | "**เครื่องตัวเอง**" ใครพิมพ์ก็หมายถึงเครื่องของคนนั้น |
| `192.168.x.x`, `10.x.x.x`, `172.16–31.x.x` | Private / LAN IP | IP ภายในวง Wi-Fi หรือ LAN เดียวกัน ใช้จากอินเทอร์เน็ตไม่ได้ |
| `0.0.0.0` | ทุกช่องทาง | ใช้ตอนเปิด server แปลว่า "รับจากทุกการ์ดเครือข่าย" |
| `10.0.2.2` | (เฉพาะ Android Emulator) | หมายถึง "เครื่องคอมที่รัน emulator อยู่" |
| `169.254.x.x` | APIPA | เครื่องหา IP ไม่ได้ (ปกติแปลว่าเน็ตมีปัญหา) |

### ⚠️ ทำไมเรื่องนี้สำคัญมากในโปรเจกต์นี้

ใน `backend/.env` มีบรรทัด

```env
MQTT_URL=mqtt://192.168.1.10:1883
```

ค่านี้ **ต้องเป็น LAN IP ของคอม ห้ามเป็น `127.0.0.1`** เพราะค่านี้ถูกส่งไปให้ ESP32
ด้วย ถ้า ESP32 ได้ `127.0.0.1` ไป มันจะพยายามต่อกับ "ตัวมันเอง" ซึ่งไม่มี Broker อยู่
สคริปต์ `mqtt/setup_mqtt.ps1` จึงมีโค้ดกันไว้

```powershell
if ($BrokerHost -eq 'localhost' -or $BrokerHost -eq '0.0.0.0' -or $BrokerHost -like '127.*') {
  throw 'BrokerHost ต้องเป็น LAN IPv4 ของคอม ห้ามใช้ localhost หรือ 127.0.0.1'
}
```

### วิธีดู IP ของเครื่องตัวเอง (Windows)

```powershell
ipconfig
```

มองหาหัวข้อ `Wireless LAN adapter Wi-Fi` (หรือ `Ethernet adapter`) แล้วดูบรรทัด

```text
   IPv4 Address. . . . . . . . . . . : 192.168.1.50
   Default Gateway . . . . . . . . . : 192.168.1.1
```

`192.168.1.50` คือ LAN IP ของคุณ (ของคุณอาจเป็นเลขอื่น)

> ⚠️ LAN IP **เปลี่ยนได้** เมื่อย้ายไปต่อ Wi-Fi วงอื่น หรือเราเตอร์รีบูต
> ถ้าเปลี่ยน ESP32 ที่เคยตั้งค่าไว้จะหา Broker ไม่เจอ ต้องตั้งค่าบอร์ดใหม่ผ่าน Bluetooth
> (`run_all.ps1` จะเตือนให้เองว่า "IP เปลี่ยนแล้ว")

## 4. Port — ช่องประตูของโปรแกรม

IP บอกว่า **เครื่องไหน** ส่วน **Port** บอกว่า **โปรแกรมไหนในเครื่องนั้น**
Port เป็นตัวเลข 0–65535

เปรียบเทียบ: IP = ที่อยู่คอนโด, Port = เลขห้อง

รูปแบบเขียน `IP:Port` เช่น `127.0.0.1:3000`

### Port ที่ใช้ในโปรเจกต์นี้ (ควรจำ)

| Port | โปรแกรม | ใครต่อเข้ามา |
|---|---|---|
| `3000` | Backend (Node.js) | แอป, เว็บ |
| `3306` | MariaDB | Backend, HeidiSQL |
| `3307` | อุโมงค์ SSH ไปฐานข้อมูลบนเซิร์ฟเวอร์ (`db-tunnel.ps1`) | HeidiSQL |
| `1883` | Mosquitto แบบไม่เข้ารหัส | Backend, ESP32 (ตอนพัฒนา) |
| `8883` | Mosquitto แบบเข้ารหัส TLS (MQTTS) | ESP32 (ตอนใช้งานจริง) |
| `80` | HTTP | Caddy (ใช้ขอใบรับรอง) |
| `443` | HTTPS | Caddy (เว็บ + API จริง) |
| `22` | SSH | ผู้ดูแลเข้าเซิร์ฟเวอร์ |
| `5500` | Python http.server | ทดสอบเว็บแอปบนเครื่อง |

### โปรแกรมเดียวจองพอร์ตได้ทีละตัว

ถ้ารัน Backend สองหน้าต่างพร้อมกัน ตัวที่สองจะพังด้วยข้อความประมาณ

```text
Error: listen EADDRINUSE: address already in use 0.0.0.0:3000
```

`EADDRINUSE` = "Address in use" = มีคนจองพอร์ตนี้แล้ว
`run_all.ps1` จึงมีขั้นตอน "ปิด Backend ตัวเก่าที่ค้างพอร์ต 3000" ก่อนเปิดใหม่

ดูว่าใครจองพอร์ตอยู่

```powershell
Get-NetTCPConnection -LocalPort 3000 -State Listen
# จะได้เลข OwningProcess (PID) แล้วดูชื่อโปรแกรมด้วย
Get-Process -Id <PID>
```

## 5. Protocol — ภาษากลางในการคุย

**Protocol** คือกติกาว่าจะส่งข้อมูลกันอย่างไร โปรเจกต์นี้ใช้หลาย protocol

| Protocol | ย่อมาจาก | ใช้ระหว่าง |
|---|---|---|
| HTTP / HTTPS | HyperText Transfer Protocol (Secure) | แอป/เว็บ ↔ Backend |
| MQTT / MQTTS | Message Queuing Telemetry Transport | Backend ↔ Broker ↔ ESP32 |
| BLE | Bluetooth Low Energy | แอปมือถือ ↔ ESP32 (ตั้งค่าครั้งแรก) |
| TCP | Transmission Control Protocol | ชั้นล่างของ HTTP, MQTT, MariaDB |
| UART | Universal Asynchronous Receiver-Transmitter | ESP32 ↔ PZEM, ESP32 ↔ LD2410 (สายไฟ 2 เส้น) |
| IR | Infrared | ESP32 ↔ แอร์ (แสงอินฟราเรดแบบรีโมต) |
| SSH | Secure Shell | คอมเรา ↔ เซิร์ฟเวอร์ |
| SMTP | Simple Mail Transfer Protocol | Backend ↔ Gmail (ส่ง OTP) |
| NTP | Network Time Protocol | ESP32/เซิร์ฟเวอร์ ↔ เซิร์ฟเวอร์เวลา |

ไม่ต้องจำทั้งหมดตอนนี้ แต่ละบทจะอธิบายตัวที่เกี่ยวข้องอีกครั้ง

## 6. HTTP — ภาษาที่แอปใช้คุยกับ Backend

### 6.1 URL คืออะไร

```text
https://rmutt-energy.duckdns.org:443/api/rooms?floor=2
└─┬─┘   └──────────┬───────────┘ └┬┘ └───┬───┘ └──┬──┘
scheme           host           port   path    query
```

- **scheme** = ใช้ protocol อะไร (`http` หรือ `https`)
- **host** = เครื่องไหน (ชื่อโดเมน หรือ IP)
- **port** = ถ้าไม่เขียน `http` = 80, `https` = 443
- **path** = ขออะไร
- **query** = ตัวเลือกเพิ่มเติม (หลัง `?` คั่นหลายตัวด้วย `&`)

### 6.2 Method — ขอแบบไหน

| Method | ความหมาย | ตัวอย่างในโปรเจกต์ |
|---|---|---|
| `GET` | ขอดูข้อมูล | `GET /api/rooms` = ขอรายชื่อห้อง |
| `POST` | สร้างใหม่ / สั่งให้ทำ | `POST /api/auth/login` = ขอเข้าสู่ระบบ |
| `PUT` | แก้ทั้งก้อน | `PUT /api/rooms/16302` = แก้ข้อมูลห้อง 16302 |
| `PATCH` | แก้บางส่วน | `PATCH /api/users/somchai` = เปลี่ยนสิทธิ์ผู้ใช้ |
| `DELETE` | ลบ | `DELETE /api/rooms/16302` = ลบห้อง |

### 6.3 Request หนึ่งครั้งหน้าตาเป็นอย่างไร

เวลาแอปล็อกอิน มันส่งข้อความนี้ไปที่ Backend

```http
POST /api/auth/login HTTP/1.1
Host: 127.0.0.1:3000
Content-Type: application/json

{"username":"admin","password":"mypassword"}
```

- บรรทัดแรก: method + path
- บรรทัดถัดมา: **Header** (ข้อมูลประกอบ)
- บรรทัดว่างหนึ่งบรรทัด แล้วตามด้วย **Body** (เนื้อหา)

### 6.4 Response ที่ได้กลับมา

```http
HTTP/1.1 200 OK
Content-Type: application/json

{"token":"eyJhbGciOi...","user":{"username":"admin","role":"admin", ...}}
```

### 6.5 Status Code — ตัวเลขบอกผลลัพธ์

| Code | ความหมาย | เจอในโปรเจกต์เมื่อ |
|---|---|---|
| `200` OK | สำเร็จ | ขอข้อมูลได้ |
| `201` Created | สร้างสำเร็จ | สร้างห้องใหม่ |
| `202` Accepted | รับเรื่องแล้ว (ยังไม่เสร็จ) | สั่งแอร์ (ส่งเข้า MQTT แล้ว รอบอร์ดทำ) |
| `400` Bad Request | ข้อมูลที่ส่งมาผิด | ไม่กรอก Username |
| `401` Unauthorized | ยังไม่ล็อกอิน / Token หมดอายุ | เรียก API โดยไม่แนบ Token |
| `403` Forbidden | ล็อกอินแล้วแต่ไม่มีสิทธิ์ | Staff พยายามลบผู้ใช้ |
| `404` Not Found | ไม่มีสิ่งนี้ | พิมพ์ path ผิด |
| `409` Conflict | ขัดแย้งกับข้อมูลเดิม | แอร์หมายเลขนี้มีแล้วในห้อง |
| `413` Too Large | ข้อมูลใหญ่เกิน | อัปโหลดไฟล์ Excel ใหญ่เกิน 256 KB |
| `429` Too Many Requests | ขอถี่เกิน | กรอกรหัสผิด 10 ครั้งใน 15 นาที |
| `500` Internal Server Error | Backend พังเอง | ฐานข้อมูลขาดคอลัมน์ |
| `503` Service Unavailable | ระบบย่อยไม่พร้อม | Backend ยังไม่ต่อ MQTT |

> 💡 จำง่าย ๆ: **2xx = ดี, 4xx = คนขอทำผิด, 5xx = เซิร์ฟเวอร์ผิด**

### 6.6 ลองเรียก HTTP เองจาก PowerShell

ถ้า Backend รันอยู่ (บท 13) ลองพิมพ์

```powershell
Invoke-RestMethod http://127.0.0.1:3000/api/health
```

- `Invoke-RestMethod` = คำสั่ง PowerShell สำหรับส่ง HTTP request แล้วแปลง JSON ให้อ่านง่าย
- ค่า default คือ method `GET`

ผลลัพธ์ประมาณ

```text
status  service                 mqtt
------  -------                 ----
ok      rmutt-save-energy-api   @{connected=True; broker=...}
```

หรือเปิดในเบราว์เซอร์ที่ `http://127.0.0.1:3000/api/health` ก็ได้

ลองส่ง POST (ล็อกอิน)

```powershell
$body = @{ username = 'admin'; password = 'รหัสของคุณ' } | ConvertTo-Json
Invoke-RestMethod -Method Post -Uri http://127.0.0.1:3000/api/auth/login `
  -ContentType 'application/json' -Body $body
```

- `@{ ... }` = สร้าง "ตาราง key-value" (hashtable) ใน PowerShell
- `| ConvertTo-Json` = แปลงเป็นข้อความ JSON
- `` ` `` (backtick) ท้ายบรรทัด = บอก PowerShell ว่า "คำสั่งยังไม่จบ ต่อบรรทัดถัดไป"

## 7. JSON — รูปแบบข้อมูลที่ทุกส่วนใช้

**JSON** (JavaScript Object Notation) คือรูปแบบการเขียนข้อมูลเป็นข้อความ
ทุกส่วนของโปรเจกต์ (แอป, Backend, ESP32, เว็บ) คุยกันด้วย JSON

```json
{
  "version": 1,
  "commandId": "a1b2c3",
  "state": {
    "power": true,
    "temperature": 24,
    "mode": "cool",
    "timerOnMinutes": null
  },
  "tags": ["room", "16302"]
}
```

กติกา

| สัญลักษณ์ | ความหมาย |
|---|---|
| `{ }` | Object — กลุ่มของ `"ชื่อ": ค่า` |
| `[ ]` | Array — รายการเรียงลำดับ |
| `"ข้อความ"` | String — ต้องใช้ฟันหนูคู่ `"` เท่านั้น |
| `24`, `229.8` | Number |
| `true` / `false` | Boolean |
| `null` | ไม่มีค่า |

> ⚠️ ข้อผิดพลาดที่พบบ่อย: ลืมจุลภาค `,` / มีจุลภาคเกินตัวสุดท้าย / ใช้ `'` แทน `"`

ตัวอย่างข้างบนคือคำสั่งแอร์จริงที่ Backend ส่งไปให้ ESP32 (ดู `docs/BLE_MQTT_PROTOCOL.md`)

## 8. Domain Name และ DNS

จำ `157.85.105.137` ยาก จึงมี **ชื่อโดเมน** เช่น `rmutt-energy.duckdns.org`
**DNS** (Domain Name System) คือสมุดโทรศัพท์ที่แปลงชื่อ → IP

ดูว่าโดเมนชี้ไป IP อะไร

```powershell
nslookup rmutt-energy.duckdns.org
```

บน Linux

```bash
dig +short rmutt-energy.duckdns.org
```

- **DuckDNS** = บริการโดเมนฟรี ใช้กับเซิร์ฟเวอร์ทดสอบของโปรเจกต์
- ตอนใช้จริงในมหาวิทยาลัยจะขอโดเมน เช่น `energy.eng.rmutt.ac.th` จากฝ่ายไอที

## 9. HTTPS, TLS และใบรับรอง (Certificate)

HTTP ธรรมดาส่งข้อมูลแบบ **อ่านได้** ถ้ามีคนดักกลางทาง (เช่นใน Wi-Fi สาธารณะ)
จะเห็นรหัสผ่านทันที

**HTTPS** = HTTP + **TLS** (การเข้ารหัส) ทำ 2 อย่าง

1. **เข้ารหัส** ข้อมูลระหว่างทาง
2. **ยืนยันตัวตน** ว่าเซิร์ฟเวอร์เป็นตัวจริง ด้วย **ใบรับรอง (Certificate)**

ใบรับรองออกโดย **CA** (Certificate Authority) ที่ทุกเครื่องเชื่อถือ
โปรเจกต์นี้ใช้ **Let's Encrypt** (ฟรี) ขอให้อัตโนมัติโดย **Caddy**

MQTT ก็ใช้แบบเดียวกัน: `mqtt://` (พอร์ต 1883, ไม่เข้ารหัส) กับ `mqtts://` (พอร์ต 8883, เข้ารหัส)

ESP32 ต้องรู้จัก **ใบรับรองราก (Root CA)** ของ Let's Encrypt ถึงจะเชื่อเซิร์ฟเวอร์
ใบนั้นฝังอยู่ในไฟล์ `firmware/rmutt_esp32_air/letsencrypt_ca.h`
และอัปเดตได้ด้วยสคริปต์ `firmware/update-root-ca.ps1`

## 10. การเข้ารหัสผ่าน: Hash ไม่ใช่ Encrypt

ระบบนี้ **ไม่เก็บรหัสผ่านจริง** ในฐานข้อมูล แต่เก็บ **hash**

- **Hash** = แปลงข้อความเป็นข้อความยาวคงที่แบบ **ทางเดียว** ย้อนกลับไม่ได้
  - `1234` → `$2b$12$l6JjOOe7Xok...` (bcrypt)
- ตอนล็อกอิน ระบบเอารหัสที่พิมพ์มา hash แล้ว **เทียบ** กับที่เก็บไว้
- ถ้าฐานข้อมูลหลุด คนร้ายก็ยังไม่รู้รหัสจริง

โปรเจกต์ใช้

| อัลกอริทึม | ใช้กับ | อยู่ในไฟล์ |
|---|---|---|
| bcrypt (cost 12) | รหัสผ่านผู้ใช้ | `backend/src/routes/auth.js` |
| HMAC-SHA256 + pepper | OTP และ reset token | `backend/src/utils/security.js` |

รายละเอียดอยู่ในบท 08

## 11. Token และ JWT — บัตรผ่านหลังล็อกอิน

HTTP **จำไม่ได้** ว่าเราเป็นใคร (stateless) ทุก request ต้องบอกตัวตนใหม่
หลังล็อกอินสำเร็จ Backend จะให้ **Token** (ข้อความยาว ๆ) มาหนึ่งอัน
แอปต้องแนบ Token นี้ไปกับทุก request ใน header

```http
Authorization: Bearer eyJhbGciOiJIUzI1NiIsInR5cCI6IkpXVCJ9.eyJzdWIiOiJhZG1pbiJ9.abc123
```

เปรียบเทียบ: ล็อกอิน = แลกบัตรประชาชนเป็นบัตรผ่านเข้าตึก ทุกประตูตรวจบัตรผ่าน

**JWT** (JSON Web Token) คือ Token แบบหนึ่ง ข้างในมี 3 ส่วนคั่นด้วยจุด
`header.payload.signature` — payload บอกว่าเป็นใคร หมดอายุเมื่อไร
signature พิสูจน์ว่า Backend เป็นคนออกจริง (ปลอมไม่ได้ถ้าไม่รู้ `JWT_SECRET`)

ในโปรเจกต์ Token หมดอายุใน 8 ชั่วโมง (`JWT_EXPIRES_IN=8h`)

## 12. Environment Variable และไฟล์ `.env`

โปรแกรมต้องรู้ค่าบางอย่างที่ **ต่างกันในแต่ละเครื่อง** และ **เป็นความลับ** เช่น
รหัสฐานข้อมูล ค่าพวกนี้ **ห้ามเขียนตายในโค้ด** แต่เก็บใน **Environment Variable**

ไฟล์ `.env` คือไฟล์ข้อความที่เก็บค่าพวกนี้บรรทัดละตัว รูปแบบ `ชื่อ=ค่า`

```env
PORT=3000
DB_HOST=127.0.0.1
DB_PASSWORD=รหัสลับ
```

- บรรทัดที่ขึ้นต้นด้วย `#` = คอมเมนต์
- `.env` **ไม่ถูกส่งขึ้น Git** (อยู่ใน `.gitignore`)
- `.env.example` = ไฟล์ตัวอย่างที่ **ไม่มีความลับ** ใช้คัดลอกไปเป็น `.env`

โปรเจกต์นี้มี `.env` 3 ที่

| ไฟล์ | ใช้โดย |
|---|---|
| `backend/.env` | Backend ตอนรันบนเครื่อง |
| `mqtt/.env` | Mosquitto ตอนรันบนเครื่อง (Username/Password ของ Broker) |
| `/opt/rmutt/.env` บนเซิร์ฟเวอร์ | ทุก container ตอนใช้งานจริง |

> ⚠️ ห้ามส่งไฟล์ `.env` ให้ใคร ห้าม screenshot ห้ามโพสต์ในกลุ่ม

## 13. สรุปบท

- Client ขอ, Server ตอบ
- IP บอกเครื่อง, Port บอกโปรแกรม — `127.0.0.1` = เครื่องตัวเอง, LAN IP = ให้คนอื่นในวงเดียวกันเข้าถึง
- HTTP มี method (GET/POST/…), header, body และ status code
- ข้อมูลส่งกันเป็น JSON
- HTTPS/MQTTS = เข้ารหัสด้วย TLS ต้องมีใบรับรอง
- รหัสผ่านเก็บเป็น hash, หลังล็อกอินใช้ Token (JWT)
- ค่าลับเก็บใน `.env`
