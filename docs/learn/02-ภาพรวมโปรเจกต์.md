# 02 · ภาพรวมโปรเจกต์ RMUTT Save Energy

> บทนี้ตอบคำถาม 3 ข้อ
> 1. ระบบมีกี่ชิ้น แต่ละชิ้นทำหน้าที่อะไร
> 2. แต่ละชิ้นอยู่ในโฟลเดอร์ไหน
> 3. ข้อมูลเดินทางผ่านชิ้นไหนบ้าง เมื่อคนกดปุ่มในแอป

---

## 1. ปัญหาที่ระบบนี้แก้

อาคาร 16 คณะวิศวกรรมศาสตร์ มทร.ธัญบุรี มีห้องกว่า 20 ห้อง แต่ละห้องมีแอร์ ปัญหาคือ

1. **คนออกจากห้องแล้วลืมปิดแอร์** — เปิดทิ้งทั้งคืน
2. **ไม่รู้ว่าห้องไหนกินไฟเท่าไร** — มีแต่บิลรวมทั้งตึก
3. **ไม่มีคนเดินตรวจได้ตลอด**

ระบบจึงต้อง **วัดไฟรายเครื่อง + รู้ว่ามีคนไหม + สั่งปิดเองได้ + ดูย้อนหลังได้**

### ① แอป Flutter — "รีโมตในมือ"
- เขียนด้วยภาษา **Dart** บนเฟรมเวิร์ก **Flutter**
- รันได้ทั้ง Android, Windows (และ Web)
- หน้าที่: ล็อกอิน, ดูห้อง, สั่งแอร์, ดูกราฟค่าไฟ, จัดการตารางเรียน, **ตั้งค่า ESP32 ผ่าน Bluetooth**
- โฟลเดอร์: `lib/` (โค้ด), `test/` (ชุดทดสอบ), `android/`, `windows/`, `web/` (ไฟล์เฉพาะแพลตฟอร์ม)

### ② เว็บแอป — "หน้าจอกว้างสำหรับแอดมิน"
- เขียนด้วย HTML + CSS + JavaScript ล้วน **ไม่ต้อง build**
- หน้าที่: ดูภาพรวมทั้งอาคาร, จัดการข้อมูลจำนวนมาก, สั่งอัปเดตเฟิร์มแวร์
- **ทำไม่ได้**: ตั้งค่า ESP32 ผ่าน Bluetooth (ต้องใช้แอปมือถือ)
- โฟลเดอร์: `webapp/`

### ③ Backend — "สมองกลาง"
- เขียนด้วย **JavaScript** รันบน **Node.js** ใช้เฟรมเวิร์ก **Express**
- หน้าที่:
  - ตรวจรหัสผ่าน ออก Token
  - อ่าน/เขียนฐานข้อมูล
  - ส่งคำสั่งไป ESP32 ผ่าน MQTT และฟังข้อมูลที่ ESP32 ส่งกลับ
  - คำนวณค่าไฟรายชั่วโมง
  - **ตัดสินใจปิดแอร์อัตโนมัติ** ทุก 10 วินาที
  - ส่งอีเมล OTP
- โฟลเดอร์: `backend/`

### ④ MariaDB — "ความจำถาวร"
- ฐานข้อมูลแบบตาราง (Relational Database) ตระกูลเดียวกับ MySQL
- เก็บ: ผู้ใช้, ห้อง, ตารางเรียน, แอร์, เซ็นเซอร์, ค่าไฟรายชั่วโมง, การแจ้งเตือน, ค่าตั้งระบบ
- โครงตารางอยู่ที่: `backend/database/schema.sql`

### ⑤ Mosquitto — "ไปรษณีย์"
- **MQTT Broker** = ตัวกลางรับ-ส่งข้อความ
- ESP32 กับ Backend **ไม่คุยกันตรง ๆ** แต่ส่งผ่าน Broker
- ตอนพัฒนาบนเครื่อง: รันด้วย Docker จากโฟลเดอร์ `mqtt/`
- ตอนใช้งานจริง: รันด้วย Docker จาก `deploy/`

### ⑥ ESP32 แอร์ — "มือ" (หนึ่งบอร์ดต่อแอร์หนึ่งเครื่อง)
- ไมโครคอนโทรลเลอร์ราคาถูกที่มี Wi-Fi + Bluetooth ในตัว
- ยิง IR เหมือนรีโมตแอร์ (ขา GPIO17)
- อ่านค่าไฟจาก PZEM-004T (ขา GPIO16/18)
- มีไฟ LED เขียว/แดง/เหลือง บอกสถานะ
- โค้ด: `firmware/rmutt_esp32_air/rmutt_esp32_air.ino` (รุ่น 2.5.1)

### ⑦ ESP32 ตรวจคน — "ตา" (หนึ่งบอร์ดต่อห้อง)
- อ่านเรดาร์ HLK-LD2410 (ขา GPIO32/33) ตัดสินว่ามีคนหรือไม่
- โค้ด: `firmware/rmutt_esp32_occupancy/rmutt_esp32_occupancy.ino` (รุ่น 1.3.0)

## 3. ทำไมต้องแยกเป็นหลายชิ้น (ไม่ให้แอปคุยกับ ESP32 หรือฐานข้อมูลตรง ๆ)

| ถ้าทำแบบนี้ | จะพังเพราะ |
|---|---|
| แอปต่อ MariaDB ตรง | ต้องฝังรหัสฐานข้อมูลไว้ในแอป ใครแกะไฟล์ APK ก็ได้รหัสไป → ลบข้อมูลทั้งหมดได้ |
| แอปคุยกับ ESP32 ตรงทาง Wi-Fi | มือถือต้องอยู่วงเดียวกับบอร์ด, สั่งจากบ้านไม่ได้, ไม่มีใครบันทึกประวัติ |
| ให้แอปตัดสินใจปิดแอร์อัตโนมัติ | ถ้าไม่มีใครเปิดแอปอยู่ ก็ไม่มีใครปิดแอร์ |
| ESP32 ต่อ Backend ด้วย HTTP | บอร์ดต้องถามซ้ำ ๆ ว่า "มีคำสั่งไหม" เปลืองและช้า MQTT ส่งถึงทันที |

หลักคิด: **Backend เป็นคนเดียวที่ถือความลับและตัดสินใจ** ส่วนอื่นเป็นแค่หน้าจอหรือมือ-เท้า

## 5. ตามข้อมูล 3 เส้นทางหลัก

### เส้นทาง A — กดเปิดแอร์จากแอป

```text
1. ผู้ใช้กดปุ่ม Power ในแอป
      lib/widgets/air_control_card.dart
2. แอปส่ง HTTP
      POST https://<โดเมน>/api/air-conditioners/ESP32-AABBCCDDEEFF/command
      Header: Authorization: Bearer <token>
      Body:   {"power":true,"temperature":24,"mode":"cool",...}
3. Backend ตรวจ token → ตรวจว่าแอร์ active → ตรวจค่าที่ส่งมา
      backend/src/routes/air-conditioners.js  ('/:deviceId/command')
4. Backend publish ข้อความ MQTT
      topic: rmutt/ac/ESP32-AABBCCDDEEFF/command
      backend/src/services/mqtt.js  (publishAirCommand)
5. Backend ตอบแอปทันที  202 Accepted  (ยังไม่รู้ว่าแอร์เปิดจริงไหม)
6. Mosquitto ส่งต่อให้ ESP32 ที่ subscribe topic นั้นไว้
7. ESP32 แปลง JSON → สัญญาณ IR → ยิงไปที่แอร์
      firmware/rmutt_esp32_air/rmutt_esp32_air.ino  (mqttCallback, sendCurrentIrState)
8. ESP32 publish สถานะใหม่กลับ
      topic: rmutt/ac/ESP32-AABBCCDDEEFF/state
9. Backend ได้รับ → UPDATE air_conditioners SET state_json = ...
10. แอปดึงข้อมูลใหม่ทุก 10 วินาที → หน้าจอเปลี่ยน
```

### เส้นทาง B — วัดไฟ (เกิดเองทุก 10 วินาที)

```text
1. ESP32 อ่าน PZEM ทุก 2 วินาที (แรงดัน, กระแส, วัตต์, kWh สะสม, ...)
2. ทุก 10 วินาที publish  rmutt/ac/<deviceId>/status
3. Backend รับ → หาผลต่าง kWh จากครั้งก่อน → บวกเข้า "ถังรายชั่วโมง"
      ตาราง energy_hourly
4. Backend อัปเดตค่าล่าสุดในตาราง air_conditioners
5. หน้ากราฟในแอป/เว็บ เรียก GET /api/energy/summary ดึงไปวาด
```

### เส้นทาง C — ปิดแอร์อัตโนมัติเมื่อห้องว่าง

```text
1. ESP32 ตรวจคน อ่านเรดาร์ทุก 250 ms → publish rmutt/occupancy/<id>/status
2. Backend บันทึก is_occupied ลงตาราง occupancy_sensors
3. ทุก 10 วินาที Backend เรียก decideAutoOff() กับแอร์ทุกเครื่อง
      backend/src/utils/auto-off.js
   - ห้องว่าง + แอร์กินไฟอยู่ + นอกคาบเรียน → เริ่มนับ 5 นาที
   - ระหว่างคาบเรียน → นับ 15 นาที (เผื่อพักเบรก)
   - มีคนกลับเข้ามา → ยกเลิกการนับ
4. ครบเวลา → Backend ส่งคำสั่ง power:false ไป ESP32 แอร์
5. ถ้าแอร์ยังกินไฟอยู่ → ยิงซ้ำทุก 20 วินาที สูงสุด 5 ครั้ง
6. สำเร็จ/ล้มเหลว → สร้างการแจ้งเตือนในตาราง system_alerts
```

บท 12 จะเจาะทุกเส้นทางแบบละเอียดถึงระดับบรรทัดโค้ด

## 6. สองสภาพแวดล้อม: บนเครื่องตัวเอง vs บนเซิร์ฟเวอร์จริง

| หัวข้อ | Development (เครื่องตัวเอง) | Production (เซิร์ฟเวอร์จริง) |
|---|---|---|
| รันอย่างไร | `run_all.ps1` | `docker compose` บน Ubuntu |
| Backend | `npm start` ในหน้าต่าง PowerShell | container `rmutt-backend` |
| MariaDB | container หรือโปรแกรมที่ติดตั้งบน Windows | container `rmutt-db` |
| Mosquitto | `mqtt/docker-compose.yml` พอร์ต 1883 | `deploy/docker-compose.yml` พอร์ต 8883 (TLS) |
| บัญชี MQTT ของบอร์ด | ใช้บัญชีเดียวกันหมด (`shared`) | แต่ละบอร์ดมีบัญชีของตัวเอง (`dynsec`) |
| ที่อยู่ API ในแอป | `http://127.0.0.1:3000/api` | `https://<โดเมน>/api` |
| HTTPS | ไม่มี | มี (Caddy + Let's Encrypt) |
| อีเมล OTP | `MAIL_MODE=console` (พิมพ์ลงหน้าจอ) | `MAIL_MODE=smtp` (ส่งจริง) |

> 💡 แอป Flutter มีค่าเริ่มต้นชี้ไปเซิร์ฟเวอร์จริง
> (`lib/config/api_config.dart` → `https://rmutt-energy.duckdns.org/api`)
> ถ้าจะทดสอบกับเครื่องตัวเองต้องใส่ `--dart-define=API_BASE_URL=...` ทุกครั้ง (บท 09)

## 7. ตัวเลขสำคัญที่ควรจำ

| ค่า | ตัวเลข | อยู่ที่ |
|---|---|---|
| Backend port | 3000 | `backend/.env` → `PORT` |
| Token หมดอายุ | 8 ชั่วโมง | `JWT_EXPIRES_IN` |
| OTP หมดอายุ | 10 นาที, ผิดได้ 5 ครั้ง | `OTP_EXPIRES_MINUTES` |
| ล็อกอินผิดได้ | 10 ครั้ง / 15 นาที | `routes/auth.js` (loginLimiter) |
| ESP32 ส่งสถานะ | ทุก 10 วินาที | `STATUS_INTERVAL_MS` |
| ESP32 อ่าน PZEM | ทุก 2 วินาที | `PZEM_READ_INTERVAL_MS` |
| ถือว่าแอร์ทำงาน | > 30 W (ปิดเมื่อ < 10 W) ยืนยัน 3 ครั้ง | `AC_RUNNING_ON_WATTS` |
| เกณฑ์เรดาร์ว่ามีคน | ค่านิ่ง (static) > 25 | `STATIC_ENERGY_THRESHOLD` |
| ปิดอัตโนมัตินอกคาบ | 300 วินาที (5 นาที) | `AUTO_OFF_IDLE_SECONDS` |
| ปิดอัตโนมัติในคาบ | 900 วินาที (15 นาที) | `AUTO_OFF_IN_CLASS_SECONDS` |
| ยิงซ้ำ | ทุก 20 วินาที สูงสุด 5 ครั้ง | `AUTO_OFF_RETRY_SECONDS`, `MAX_ATTEMPTS` |
| Token ตั้งค่าบอร์ด | ใช้ได้ 15 นาที (900 วินาที) | `routes/air-conditioners.js` |
| บอร์ดเก็บข้อมูลตอนเน็ตหลุด | ~7 วัน (2,048 รายการ ทุก 5 นาที) | `history_log.h` |
