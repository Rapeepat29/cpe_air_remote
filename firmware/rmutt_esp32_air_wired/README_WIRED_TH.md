# rmutt_esp32_air_wired — ตัวควบคุมแอร์ผ่านสายแอร์ (Daikin SLM8)

เฟิร์มแวร์นี้ใช้แทนรีโมตติดผนัง Daikin ที่ถอดออก ESP32 คุยกับแอร์ทางสายแอร์โดยตรง
แอป, Backend, BLE, MQTT, PZEM, ตารางเวลา, OTA และข้อมูลย้อนหลังใช้ร่วมกับรุ่น IR ได้ทุกอย่าง
ไม่ต้อง migrate ฐานข้อมูล (คอลัมน์ `protocol` เดิมเก็บค่า `DAIKIN_WIRED` ได้เลย)

## ผู้ใช้เห็นว่าเป็น "Daikin · สายแอร์"

ตั้งแต่รุ่นแรก 2.5.1-slm8 (ปัจจุบัน 2.5.2-slm8) บอร์ดบอกตัวเองว่าเป็นบอร์ดสายแอร์ แอป, เว็บ และ Backend จึงแสดงให้ผู้ใช้เห็นทุกที่

| ที่ | ผู้ใช้เห็น |
|---|---|
| แอป ขั้นตั้งค่าบลูทูธ | ใต้รหัสบอร์ดขึ้น "ชนิดบอร์ด: ควบคุมผ่านสายแอร์ (ใช้แทนรีโมตติดผนัง)" · ช่องยี่ห้อล็อกเป็น **Daikin · สายแอร์** เลือกยี่ห้อ IR ไม่ได้ · กล่องอธิบายฟังก์ชันที่ใช้ได้ |
| แอป การ์ดแอร์ในห้อง | ป้ายสีฟ้า 🔌 **Daikin · สายแอร์** (บอร์ด IR เป็นป้ายสีเทา เช่น Haier · รีโมต IR) |
| แอป รีโมตเต็ม | ป้ายเดียวกัน + บอกว่าใช้ได้เฉพาะฟังก์ชันของรีโมตติดผนัง · ปุ่มที่แอร์ทำไม่ได้ถูกซ่อน |
| เว็บ หน้าห้อง | ชิป **Daikin · สายแอร์** · ปุ่มโหมด/พัดลม/ส่าย/ฟังก์ชันเสริม เหลือเท่าที่ใช้ได้ |
| เว็บ หน้าอุปกรณ์ | รายการแอร์ขึ้น "Daikin · สายแอร์" · ฟอร์มจองมีตัวเลือก "Daikin · สายแอร์ (บอร์ดแทนรีโมตติดผนัง)" |

ทำงานอย่างไร

1. บลูทูธ: identity มี `"controlType":"wired","brand":"Daikin"` (บอร์ด IR ตั้งแต่ 2.5.0 ส่ง `"controlType":"ir"`, บอร์ดเก่าไม่มีช่องนี้ = IR)
2. แอปเห็น `wired` → ส่งโปรโตคอล `DAIKIN_WIRED` ไปจองกับ Backend
3. บอร์ดบันทึก `DAIKIN_WIRED` เสมอ ถึงแอปรุ่นเก่าจะส่งยี่ห้อ IR มาก็ตาม
4. MQTT status มี `"controlMode":"wired"` → ถ้าฐานข้อมูลยังเป็นยี่ห้อ IR (ตั้งด้วยแอปรุ่นเก่า) Backend แก้เป็น `DAIKIN_WIRED` ให้เอง
5. Backend ตรวจคำสั่งของ `DAIKIN_WIRED`: โหมด Cool/Dry/Fan · ไม่มีพัดลม Turbo · ส่ายเฉพาะ Auto/Off · ปิด Eco/Turbo/Quiet/Clean/ส่ายแนวนอน · ปิด Sleep ในโหมด Dry
   และ API ส่ง `controlType: "wired" | "ir"` มากับแอร์ทุกเครื่อง

## สิ่งที่เหมือนรุ่น IR ทุกตัวอักษร

- BLE: ชื่อ `RMUTT-AC-xxxx`, UUID, ขั้นตอนตั้งค่า Wi-Fi/MQTT/ห้อง/เครื่อง
- MQTT topic: `command`, `state`, `status`, `provision`, `provision-ack`, `schedule-status`, `history`, `history-ack`
- รูปแบบ JSON ของ `command` / `state` / `status` เดิม (status มีช่องเพิ่ม ดูด้านล่าง)
- PZEM-004T (RX GPIO16, TX GPIO18), ไฟ LED เขียว/แดง/เหลือง (GPIO25/26/27), ปุ่ม BOOT
- เปิด–ปิดตามเวลา, Timer, คำสั่ง `enter_setup`, `ota`, `unprovision` (ตั้งแต่ 2.5.2-slm8), ข้อมูลย้อนหลังตอนเน็ตหลุด
- ลบบอร์ดในแอป (`unprovision`): บอร์ดล้าง NVS และข้อมูลย้อนหลัง แล้วรีบูตเข้าโหมดตั้งค่าบลูทูธ
  ต่างจากรุ่น IR ตรงที่สถานะแอร์ที่จำไว้ถูกล้างด้วย หลังรีบูตบอร์ดจึงส่งเฟรมสั่งแอร์ **ปิด** ทางสาย

## สิ่งที่ต่างจากรุ่น IR

| เรื่อง | รุ่น IR | รุ่นสายแอร์ |
|---|---|---|
| ช่องทางสั่งแอร์ | ยิง IR ครั้งเดียว | ส่งเฟรมทุก 1 วินาทีตลอดเวลา ใน task แยก (ไม่สะดุดตอนต่อ Wi-Fi/MQTT/OTA) |
| รีบูตบอร์ด | ไม่มีผลกับแอร์ | ส่งค่าที่จำไว้ใน NVS ตั้งแต่เฟรมแรก แอร์ไม่ดับเอง |
| อุณหภูมิห้อง | ไม่มี | DHT11 → ส่งให้แอร์ใช้ตัดคอมเพรสเซอร์ (แทนเซนเซอร์ในรีโมตผนัง) |
| สถานะจากแอร์ | ไม่มี | สายตอบไหม, คอมเพรสเซอร์ทำงานไหม, อุณหภูมิที่แอร์รายงาน |
| ยี่ห้อในแอป | ผู้ใช้เลือกให้ตรงรีโมต | บอร์ดบอกเอง: **Daikin · สายแอร์** (`DAIKIN_WIRED`) เลือกไม่ได้ |

### ฟังก์ชันที่แอร์รับได้ทางสาย

เปิด/ปิด · 16–30 °C · Cool / Dry / Fan · พัดลม Low / Medium / High / Auto · ส่าย เปิด/ปิด · Sleep

แอปและเว็บแสดงเฉพาะปุ่มเหล่านี้ และ Backend ไม่รับคำสั่งนอกเหนือจากนี้
ถ้ามีคำสั่งหลุดมาถึงบอร์ด (เช่น จากแอปรุ่นเก่า) เฟิร์มแวร์ปรับให้ตรงกับที่แอร์ทำได้ แล้วส่งค่าจริงกลับใน `state`:

| แอปสั่ง | ที่ส่งไปแอร์จริง |
|---|---|
| Mode Auto / Heat | คงโหมดเดิม |
| Fan Turbo | High |
| ตำแหน่งใบพัด top/upper/middle/lower/bottom | ส่าย |
| Eco, Turbo, Quiet, Clean, ส่ายแนวนอน | ปิด |
| Sleep ในโหมด Dry | ปิด (แอร์ไม่รับ) |

### ช่องที่เพิ่มใน `status`

Backend ใช้ `controlMode` แก้โปรโตคอลเป็น `DAIKIN_WIRED` ช่องอื่นยังไม่ได้อ่าน

```json
"controlMode": "wired",
"airBrand": "Daikin",
"busOk": true,
"compressorRunning": true,
"unitRoomTemperature": 27,
"roomTemperature": 27.4
```

## ต่อสาย

| ขา ESP32 | ต่อกับ | หมายเหตุ |
|---|---|---|
| GPIO33 | **ขาที่มีแถบ** ของ 1N4148 · ขาไม่มีแถบ → สายสั่งงาน (panel → แอร์) | **ย้ายมาจาก GPIO25** เพราะ GPIO25 เป็นไฟ LED เขียวของเฟิร์มแวร์แอป |
| GPIO35 | สายสถานะ (แอร์ → panel) ผ่าน 100k / 200k ลง GND | |
| GPIO34 | สายสั่งงาน ผ่าน 100k / 200k ลง GND | ตรวจสัญญาณตัวเอง ไม่บังคับ (`BUS_ECHO_PIN = -1` ถ้าไม่ต่อ) |
| GND | GND สายแอร์ | **ต้องต่อ** |
| — | +5V สายแอร์ | **ไม่ต่อ** (ใช้ HDR-15-5) |
| GPIO4 | DHT11 ขา DATA (Keyes KY-015) · + → 3V3 · − → GND | |
| GPIO21 / GPIO22 | OLED SDA / SCL · VCC → 3V3 · GND → GND | |
| GPIO16 / GPIO18 | PZEM TX / RX | เหมือนรุ่น IR |
| GPIO25 / 26 / 27 | LED เขียว / แดง / เหลือง (ผ่าน R 220–330 Ω) | เหมือนรุ่น IR |

ถ้าใช้ 2N2222 แทนไดโอด: ตั้ง `BUS_TX_INVERT = true`

## ทดสอบหลังแฟลช

1. Serial Monitor 115200 ต้องเห็น `Aircon bus: TX GPIO33 (1N4148), RX GPIO35, echo GPIO34`
2. ตั้งค่าผ่านแอปเหมือนบอร์ด IR · ใต้รหัสบอร์ดต้องขึ้น "ชนิดบอร์ด: ควบคุมผ่านสายแอร์" และช่องยี่ห้อล็อกเป็น Daikin · สายแอร์
3. หน้าจอ OLED: ป้าย `BUS` ทึบ = แอร์ตอบ, ถ้าแอร์ไม่ตอบเกิน 15 วิ จะสลับขึ้นหน้าเตือน
4. กดเปิดแอร์ในแอป → Serial ขึ้น `Wired sent: power=ON ...` และแอร์ติด
5. หลังแอร์ทำงานสักพัก หน้าจอขึ้น `COMP ON` ตามที่แอร์รายงาน
